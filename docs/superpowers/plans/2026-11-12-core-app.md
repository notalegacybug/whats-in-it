# Ingredient Safety, Plan 1 of 3: Core App on the Device

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app that reads an ingredient label from a photo or screenshot, sorts each ingredient into a cited verdict using a bundled reference, and saves products and "my scans" on the device, with no server.

**Architecture:** A build-time script turns official carcinogen lists plus open ingredient inventories into one static `reference.json`. The app loads that file, reads label text on the device with Tesseract.js, and matches ingredients to the reference by exact normalised name only. Products are stored as ingredient lists behind a `ProductStore` interface (IndexedDB now, a remote implementation in plan 2); verdicts are never stored, always recomputed from the current reference.

**Tech Stack:** Node 20+, TypeScript, Vite, React 18, react-router, Vitest, React Testing Library, Playwright, Tesseract.js, `idb`, `fake-indexeddb` (tests), `fastest-levenshtein`, `papaparse`, `tsx`, `vite-plugin-pwa`.

**Spec:** `docs/superpowers/specs/2026-11-12-ingredient-safety-design.md`

**Where this plan narrows the spec (owner to confirm):**
- Hand-checked notes are written for listed ingredients that also appear in the ingredient inventories, meaning the ones that can turn up on a label. Listed substances that are not product ingredients get no note. The spec said every listed entry.
- Ordinary ingredients show the inventory's function word only. The spec's fuller notes for "the few hundred most common ingredients" are left for later.
- Saved products hold the ingredient list and reference version, not matched reference ids; verdicts are recomputed on display. Matched ids are added in plan 2, where brand reports need them.

**Later plans (not here):** plan 2 = shared library server, barcode shortcut, "report a problem"; plan 3 = Cloudflare Pages hosting, Capacitor Android build, Google Play closed test.

## Global Constraints

- No AI or paid service is called at scan time. No per-scan cost.
- Images never leave the device. During a scan the app makes no request to any other origin.
- Verdicts come only from `reference.json`. The app never writes "safe". Exact labels, from `src/copy.ts`:
  - `Watch for (strong evidence)`
  - `Watch for (possible)`
  - `No known concern on these lists`
  - `Not recognised`
- Level rules: strong = IARC `1`, NTP `Known to be a human carcinogen`, EU `Carc. 1A` or `Carc. 1B`. Possible = IARC `2A` or `2B`, NTP `Reasonably anticipated to be a human carcinogen`, Prop 65 cancer listing, EU `Carc. 2`.
- Matching an ingredient to a reference entry is exact on the normalised name. Fuzzy matching only produces a "did you mean" suggestion on the review screen; it never changes a verdict by itself.
- Every "watch for" result shows source name, classification, year and URL.
- No personal data, user id or device id is stored anywhere.
- English labels only.
- Disclaimer copy, exact: `Not medical advice. Results show whether an ingredient appears on published cancer hazard lists. A listing describes a hazard, not the risk from this product.`
- Each task ends with `git add` of its files and one commit.

## Review Focus

1. Text reading returns nothing or garbage: the review screen opens with an empty editable list and the message `We couldn't read any ingredients. Type or paste them below.` It never shows an all-clear result. (Task 11)
2. One label item holding several names (`Aqua/Water/Eau`, `Titanium Dioxide (CI 77891)`, `Wheat flour (wheat flour, calcium carbonate)`): every part is checked and the most severe verdict wins. (Tasks 2, 3)
3. A misread flagged name (`Forma1dehyde`): shown as `Not recognised` with a suggestion, never as `No known concern on these lists`. (Tasks 3, 4)
4. An everyday word colliding with a listed exposure that is not an ingredient (`alcohol` vs IARC "Alcoholic beverages", `wood` vs "Wood dust"): entries without a CAS number are left out of the reference unless allow-listed. (Task 6)
5. `reference.json` fails to load: the app shows an error with a retry button and blocks analysis; no result is ever shown without a reference. (Task 8)

```ts
export type SourceId = 'IARC' | 'NTP' | 'PROP65' | 'EU_CLP';
export type Level = 'strong' | 'possible';
export interface Listing { source: SourceId; classification: string; level: Level; year: number | null; url: string; qualifier?: string }
export interface RefEntry {
  id: string;            // "cas:50-00-0" or "name:<normalised name>"
  name: string; aliases: string[]; cas: string[];
  listings: Listing[];   // empty for ordinary catalogue entries
  note?: string;         // hand-checked note
  functionNote?: string; // inventory function, e.g. "humectant"

export interface Reference { version: string; builtAt: string; entries: RefEntry[] }
export type Verdict = 'watch_strong' | 'watch_possible' | 'no_known_concern' | 'not_recognised';
export interface Match { key: string; verdict: Verdict; entry: RefEntry | null }
export interface IngredientResult { input: string; verdict: Verdict; matches: Match[] }
export interface RefIndex { version: string; byKey: Map<string, RefEntry>; keys: string[] }
export function buildIndex(ref: Reference): RefIndex;          // keys = normalised name, aliases, CAS numbers
export function analyseIngredient(input: string, index: RefIndex): IngredientResult;
export function analyse(ingredients: string[], index: RefIndex): IngredientResult[]; // input order
export const SEVERITY: Verdict[]; // ['watch_strong','watch_possible','not_recognised','no_known_concern'], also the display order
```

```ts
export type ProductType = 'food' | 'cosmetic';
export interface NewProduct { name: string; brand: string; type: ProductType; barcode: string | null; ingredients: string[]; referenceVersion: string }
export interface ProductRecord extends NewProduct { id: string; createdAt: string }
export interface ProductStore {
  findMatches(p: NewProduct): Promise<ProductRecord[]>;
  save(p: NewProduct): Promise<ProductRecord>;
  get(id: string): Promise<ProductRecord | null>;
  search(text: string): Promise<ProductRecord[]>;   // name or brand contains text, case-insensitive, newest first
}
export function ingredientSimilarity(a: string[], b: string[]): number;  // Jaccard on normalised names
export function isLikelySame(a: NewProduct, b: NewProduct): boolean;

export function listScans(): Promise<{ productId: string; scannedAt: string }[]>;  // newest first
```
